# Sample Idea Submission — Low AI Score Target

Use this sample to exercise the low-score validation path. It is deliberately vague and lacks evidence, a defined user group, a specific process, implementation detail, and measurable success criteria. It is intended to score below **5/10**, but Gemini scores can vary between runs and an exact score cannot be guaranteed.

## Step 1 — Describe

- **Type:** An idea
- **Your idea in your own words:**

  The bank should use AI to improve branch service. Staff could have a dashboard that helps with customer problems. It might make things faster and easier. We should try it in branches and see if people like it.

- **Potentially related ideas:** Search results depend on existing submissions. If a genuinely related idea appears, select it and enter the distinction below. Do not select an unrelated idea just to continue.
- **How is your idea different?** *(Only required if related ideas are shown and none is selected.)*

  This suggestion is about a general branch dashboard; it does not identify a specific customer problem or workflow.

## Step 2 — Develop

- **Idea title:** AI Dashboard for Better Branch Service
- **Summary:** Add an AI dashboard to help branch staff serve customers faster. The dashboard could bring useful information together, but the information, users, and actions have not been identified yet. A branch could try it and decide whether it is helpful.
- **Problem statement:** Branch service can be slow sometimes. I do not know which branch process takes the longest, how often the issue occurs, or which customers or staff are most affected.
- **Proposed solution:** Make an AI dashboard for branch staff. It could show customer information and suggest what to do, but I have not identified the systems, data, workflow, safeguards, or exact functions it would need.
- **Expected benefits:** Customers might get faster service and staff might find information more easily. There is no measured baseline or estimate of how much time or effort this would save.
- **Possible risks:** The dashboard might show incorrect information or create privacy concerns. I have not worked out how to prevent these problems or who should review the suggestions.

## Step 3 — Questions reviewers may ask

- **Who experiences this problem today?** Branch staff and customers, but I have not identified a specific role, customer group, or branch process.
- **What happens today?** Staff use the existing branch systems. I have not observed or documented the steps that cause the delay.
- **What is needed to make this work?** A dashboard, some customer information, and AI. I have not confirmed the required data, system access, owner, controls, or technical effort.
- **What could make the proposal difficult?** It could be expensive, show incorrect information, or be hard to use. I do not have details on how likely these issues are or how to reduce them.
- **How would you know the change worked?** Ask staff and customers whether they like it. I have not defined a baseline, target, measurement period, or error and safety measures.

## Step 4 — AI validation

1. Select **Check with AI**.
2. Intended result: a low score, preferably **below 5/10**. This content is intentionally missing evidence, scope, feasibility, safeguards, and measurable outcomes. The model may still score it differently.
3. A score of **7/10 or below does not pass** the normal validation gate. Use the AI's reported gaps to understand why.

### If you need to complete the low-score submission path

The app requires **two successful below-threshold validations on different draft versions** before it offers **Continue to human review submission**. After the first low result:

1. Choose **Improve draft**.
2. Make a small edit to create a new draft version while keeping the proposal intentionally underspecified. For example, append this sentence to the summary: “The team, data sources, controls, expected volume, and measurable target are still undecided.”
3. Run **Check with AI** again on that changed version. The second score must also be 7 or below.
4. Continue to human review submission when the button appears. This routes the idea for a person to assess; it does not mean the idea is approved.

If either validation scores above 7, the normal path is available instead. If the preflight safety check fails, follow the error and revise the content; AI validation alone cannot bypass that check.

## Step 5 — Impact numbers

Impact scores are separate from the AI validation score. Enter values from **0 to 3**. The sample uses **2.0** for each field, which produces a default weighted priority score of **2.00/3** under the default weights. The administrator can change the minimum and weights, so confirm the live minimum shown in the form before submitting.

| Field | Score | Explanation |
|---|---:|---|
| Turnaround time | 2.0 | A faster service time is possible, but no branch workflow or baseline has been measured. This is an unverified placeholder estimate. |
| Volume | 2.0 | Multiple branches might be affected, but the number of eligible cases or customers is unknown. This is an unverified placeholder estimate. |
| Expected savings or revenue | 2.0 | Staff time might be saved, but no effort, cost, or revenue estimate exists. This is an unverified placeholder estimate. |

- **Turnaround explanation:** No baseline is available. A pilot would need to measure time spent on one selected branch workflow before and after a change.
- **Volume explanation:** No case count is available. The process owner would need to identify the workflow and obtain an approved aggregate volume.
- **Value explanation:** No validated financial estimate is available. Any value would need to be calculated from measured time or cost and reviewed by the relevant owner.

## Before submitting

- Confirm the live priority result meets the minimum displayed by the form. If the minimum is above this sample's score, adjust the impact values or ask the administrator which threshold is configured.
- Run validation again after changing any draft content; a score for an older draft cannot authorize submission.
- Complete all five reviewer answers and all three impact scores and explanations.
- Use fictional, non-sensitive examples only. Do not enter account numbers, customer names, card data, live payment references, credentials, or other restricted information.
